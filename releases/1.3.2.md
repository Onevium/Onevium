# Onevium 1.3.2 — Evidence-backed memory, browser identities with network routes, and a menu-bar hub

Onevium 1.3.2 rebuilds memory so every memory shows where it came from, and answers mark the memories they used. The built-in browser supports several identities, each with its own sign-ins and network route. This release also adds a menu-bar hub, conversation notifications, scheduled database backups, and Qwen and Xiaomi MiMo providers.

- **Evidence-backed memory:** memories are extracted only from what you said or confirmed, and each one shows its source conversation, evidence, and change history. All memories live in Settings → Personalization → Memory space, where you can see how a memory connects to others and check how often it is used and what it affects. Answers mark the memories they used; open a marker to see the evidence. Deleting, rewinding, and forgetting behave more predictably, and forgotten content is never recalled again. All 1.3.1 memories are kept; the vector index is rebuilt in the background after the upgrade without downloading the model again. [Memory and recap](https://onevium.com/docs/memory-and-recap)
- **Browser identities and network routes:** save several identities in the built-in browser, each with its own cookies, sign-ins, and network route (HTTP, HTTPS, or SOCKS5, with optional credentials). New tabs remember the identity per conversation, and AI asks when it is unsure which identity to use. Site permission requests appear as Chrome-style bubbles, and signing in offers to save the password. Manage routes in Settings → Network. [Browser automation](https://onevium.com/docs/browser-automation)
- **Menu-bar hub:** open the hub from the macOS menu bar (the system tray on Windows) to see conversations waiting for you, running, and recent, plus usage for today and the last seven days. Search and copy one-time codes and passwords from your secrets in one list, or generate a password; passwords you copy or save are kept in an encrypted local history. The icon shows how many conversations are waiting.
- **Notifications and the Dock:** get system notifications when a conversation finishes, needs confirmation, or fails, with sound and display set per category. The Dock menu opens waiting, running, and recent conversations directly, and the window title follows the current conversation.
- **Data and storage:** scheduled online database backups and storage management. When local data is upgraded, the startup screen shows real progress for backup, verification, and migration.
- **Providers and models:** new presets for Alibaba Cloud Qwen (China, International, and Coding Plan) and Xiaomi MiMo (including Token Plan), and every provider's models synced as of 2026-10-25, including Kimi K3.1 Pro, Gemini 4 Argon, and MiniMax M3.1 Flash. GPT reasoning summaries now appear when you use the official OpenAI service. [Providers](https://onevium.com/docs/providers)
- **Images and organization:** image templates are grouped into categories, every template has a preview, and the layout is refined. Title organization matches existing labels first.
- **System permissions:** Settings shows the status of screen recording, microphone, accessibility, and other system permissions in one place, with recovery steps.
- **Fixes:** an interrupted sign-in refresh or a gateway error no longer signs you out; native replies without text deltas are no longer lost; on Windows the server is shut down cleanly before being forced; channel permission requests accept answers only from users on the bot's allowlist; secret masking no longer cuts escape sequences; clicking in the browser address bar places the cursor; cookie import keeps host-only cookies host-only, fixing Google's CookieMismatch; long replies render their Markdown once.

## Before you upgrade

Full upgrade steps and recovery notes: [Install and update Onevium](https://onevium.com/docs/installation#updates).

- **The first launch upgrades local data; no downgrade.** 1.3.2 backs up and verifies the database before updating its format. Large libraries can take a few minutes; the startup screen shows progress, so do not force quit. 1.3.1 cannot read the upgraded data directly. The pre-upgrade backup is in `upgrade-backups` under the data directory. To go back, quit Onevium, replace `onevium.db` with the backup, and delete `onevium.db-wal` and `onevium.db-shm` in the same folder.
- **macOS: install this update manually.** 1.3.1 cannot complete this update in the app. Quit Onevium, then download the DMG for your chip and replace the app. From 1.3.2 on, the app is signed with a stable "Onevium" signature (not notarized by Apple), so later versions can update in the app.
- **macOS permissions and Keychain.** With the new signature, grant screen recording, microphone, and input monitoring once more; later versions keep these permissions. Keychain is different: each new version asks for your login password once on first launch. Choose Always Allow. Denying does not lose data, but saved provider keys and similar items cannot be read until you allow access.
- **Memory:** memory vectors are rebuilt in the background after the upgrade. The time depends on how many memories you have; keyword recall keeps working meanwhile. Memory model calls now count their real cost against the daily budget (1.3.1 charged a rough amount per saved memory). Unpriced custom connections are estimated at small-model rates and CNY prices are converted. Early installs that never set a budget now default to $1 a day instead of $0.10; budgets you set are unchanged. If memory says today's budget is used up, raise it in Settings → Personalization.
- **Changed defaults:**
  - A 1.3.1 proxy that was switched on with an incomplete address or port (or an invalid port) is treated as off, matching the direct connection 1.3.1 actually made.
  - ⌥⌘K and ⌥⌘T are no longer assigned by default; bind them in keyboard shortcut settings if you use them.
  - A hub icon appears in the menu bar.
  - Channel bot permission requests can be answered only by users on the bot's allowlist. If a bot accepts direct messages from anyone but its allowlist is empty, add allowed users in Channels.
  - Retired MiniMax Preview and M2.7 models switch to M3.1 Flash.
  - Custom connections that point at Qwen or MiMo addresses pick up the new presets' compatibility settings, and roles you did not set use the preset's recommended models.
- **Windows installation.** Update in the app or run the installer below. The installer is unsigned; only handle system warnings after verifying the official source and checksum. Installation, startup, and upgrades over an existing version have not been tested on a real Windows environment.
